# Kalshi 官方账户盈亏曲线

交易工作区的收益与成交账本页新增独立 Kalshi 官方曲线。账户选择沿用主工作区的单账户、全部活跃账户和全部账户范围；暂停账户仍可单独查看。Polymarket 曲线及其原有计算方式不变。

曲线直接采用官方账户整体 `cumulative_pnl`，不以本地区间开仓指标或未扣手续费收益替代；二者范围独立。后端需要配置相应账户的可选 `official_user_id`，浏览器不接收该身份、API Key 或签名。

## 数据接口

- `GET /api/console/kalshi-pnl/accounts` → Trading `/api/v1/kalshi-pnl/accounts`。
- `GET /api/console/kalshi-pnl?execution_account_id=kalshi%3Amain&range=1w` → Trading 同名只读接口。
- BFF 仅允许固定资源、单值账户及 `1d/1w/1m/1y/all`，使用服务端只读令牌，并传播调用方取消。
- 严格解码平台、账户、周期、金额、时间、采样精度及历史水位；缺值不补0，失败支持重试。

## 周期和时间精度

- 1天、1周、1个月、1年、全部分别使用官方 `1d/1w/1m/1y/all`；区间金额为首末点累计值之差，全部为末点累计值。
- 年初至今从 `1y` 中截取浏览器本地年初至今，保留年初前最近有效点作为基准。日级边界不精确匹配时，明确标注日级近似和实际计算采样；历史不足时注明真实起点。
- 自定义使用日期与00–23小时下拉，沿用本地整点/DST歧义校验。草稿仅应用后生效。
- 按开始时间距今选择能覆盖基准的最小官方周期，不能因区间长度仅12小时就取最近1天。近30天优先小时或10分钟序列，较早历史取每日序列。自定义范围结束于近期时，额外读取 `1m` 小时序列补齐最近30天，覆盖其中每日点和临时末点，保留原始累计值。拼接前校验同账户、至少一个位于两源共同历史水位内的重叠点，所有稳定重叠点的盈亏和账户价值必须一致；不平移、不插值填值。无共同点或数据冲突时提示重试。
- 较早、不超过一天的范围没有准确日级边界时，提示“该时间段仅有每日数据，请扩大范围或按整日查看。”，不显示金额与曲线。整日边界恰有两个有效点可以计算；长日级范围保留实际采样及近似提示。
- 混合序列的基准和末点各按所在分段的精度检查覆盖；每日段容差26小时以覆盖夏令时，小时段容差1小时。每日到小时交界允许每日正常间距，进入小时段后严格拒绝小时缺口。早期边界不精确匹配时仍提示区间近似；采样说明标明“早期1天 / 近期1小时”。所有快捷周期保持原算法。
- 自定义基准、末点不得晚于选中边界。缺边界覆盖或明显中间缺口时不计算收益；图轴仍对应已应用范围，域外基准不参与绘图和悬停。
- `processed_through` 为官方历史处理进度，`fetched_at` 为本系统读取时刻；官方末尾可能附带实时账户点。保留各字段原义，卡片“数据时间”对应真实采样末点，不把历史水位改写成实时末点。

图形复用现有单调平滑 SVG、真实时间轴和鼠标/触摸/键盘交互。单卡响应身份及取消隔离避免迟到结果覆盖当前周期；客户端成功缓存最多60秒，64项，过期或自定义结束时刻超过缓存读取时刻会重新读取。

## 验证

`tests/kalshi-pnl.test.ts` 覆盖 DTO、安全BFF、数据源周期选择、年初边界、小时差额/轴域、旧日期短区间、每日近似、缺口和取消。浏览器验收还需覆盖活跃账户隔离、原PM不串账户、六快捷周期、小时表单、金额与悬停、错误重试、迟到响应、隐藏Tab请求门禁及390px布局。

该接口来自 Kalshi 官网现用接口，未列入公开 Trade API 合同；上游结构或权限变化时安全报错，不回退为本地收益或零值。
